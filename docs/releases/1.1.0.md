# AgentBarrier 1.1.0

AgentBarrier 1.1.0 makes local human approval easier without weakening the production security
boundary. A trusted terminal operator can review pending actions, inspect their exact bindings, and
approve or reject them through an interactive menu instead of copying an action identifier into a
second command.

## What's new

- `agentbarrier approvals review` lists pending actions and lets a reviewer select one by number.
- Before any decision, the menu displays the exact tool, arguments, policy, requester, organization,
  namespace, idempotency key, request digest, creation time, and expiration time.
- Reviewers can approve, reject, return to the pending list, or quit without changing an action.
- Reviewer identity defaults to the current operating-system user and can still be supplied with
  `--decided-by`.
- The credential-free refund example can now approve and execute a new refund in one command while
  preserving exact-once execution and replay.
- Explicit approve and reject commands remain available for scripts and operational tooling.
- Non-interactive input cannot drive the menu; piped decisions fail closed.

## Install

```bash
python -m pip install agentbarrier==1.1.0
```

Install optional integrations only when needed, for example:

```bash
python -m pip install 'agentbarrier[mcp,service,postgres-binary,observability]==1.1.0'
```

## Try the interactive reviewer

Review an existing pending action from a trusted local terminal:

```bash
agentbarrier approvals review --db agentbarrier.db --decided-by alice
```

Or, from a repository checkout, run the credential-free refund demonstration with a new database
and request identifier. It shows the exact refund and offers `Approve and execute`, `Reject`, or
`Leave pending`:

```bash
python -m examples.runtime_refund \
  --db /tmp/agentbarrier-demo-runtime.db \
  --ledger /tmp/agentbarrier-demo-refunds.db \
  --request-id refund-demo-1 \
  --account-id customer-42 \
  --amount 100
```

Reusing the same request identifier returns the stored result without asking for approval again.
That replay is intentional and prevents retries from executing the refund twice.

## Security boundary

The terminal menu is a local usability feature, not an authentication system. Its reviewer identity
is asserted by the caller. Shared and production deployments should continue to use the
authenticated dashboard, HTTP API, or Slack integration with requester/reviewer separation.

AgentBarrier protects only tools and credentials routed through its boundary. It does not intercept
an unrestricted shell or an unmediated copy of a consequential credential.

## Upgrade from 1.0.0

This release adds no database migration and makes no incompatible public API change. Existing
explicit CLI approval commands and programmatic integrations continue to work unchanged. Upgrade in
a clean environment, run `agentbarrier --version`, and perform the installed-wheel runtime audit
before changing a production deployment.
