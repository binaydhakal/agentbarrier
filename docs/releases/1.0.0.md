# AgentBarrier 1.0.0

AgentBarrier 1.0.0 is the first stable release of the runtime policy and approval control plane for
consequential AI-agent actions. It consolidates the completed 0.4 runtime, 0.5 integration, and 0.6
team-operations development milestones; those milestone versions were not separately published.

## What it does

Place AgentBarrier immediately before a payment, database write, deployment, external message, or
other consequential tool. It evaluates deterministic policy, binds any approval to the exact
arguments and business idempotency key, claims execution once, replays recorded results without
calling the tool twice, and emits an integrity-linked audit trail outside model-visible state.

The release includes:

- synchronous and asynchronous protected Python functions plus transport-neutral dispatch APIs;
- SQLite for local or single-process use and PostgreSQL for shared production deployments;
- stdio and Streamable HTTP MCP gateways using the official MCP Python SDK;
- a scoped HTTP approval API, server-rendered dashboard, signed webhooks, and Slack approvals;
- OpenAI Agents, LangGraph, PydanticAI, and Google ADK runtime tool integrations;
- organization isolation, users, service identities, reusable roles, scoped decisions, and
  requester/reviewer separation;
- durable emergency pauses and atomic action or integer-value limits;
- privacy-safe OpenTelemetry spans, low-cardinality metrics, and structured lifecycle logs; and
- a non-root, read-only container baseline with separate migration and runtime database roles.

## Install

Install only the integrations used by the deployment:

```bash
python -m pip install agentbarrier==1.0.0
python -m pip install 'agentbarrier[mcp,service,postgres-binary,observability]==1.0.0'
python -m pip install 'agentbarrier[slack,postgres-binary]==1.0.0'
```

Framework integrations use their matching extras: `openai`, `langgraph`, `pydantic-ai`, or
`google-adk`. CrewAI remains an isolated compatibility-test extra because its OpenAI SDK dependency
conflicts with the OpenAI Agents extra.

## Upgrade from 0.3.0

The original deterministic safety-test API remains available. Runtime enforcement is opt-in: an
existing test-suite integration does not begin mediating production tools merely by upgrading.

Before moving a runtime database:

1. stop every AgentBarrier writer;
2. create and verify a backup using the documented database procedure;
3. install 1.0.0 in a clean environment;
4. run `agentbarrier database migrate` with the migration identity;
5. run `agentbarrier database status --json` and verify both receipt chains; and
6. restart runtime services with the least-privilege identity.

SQLite schema version 1 and later are migrated atomically to schema version 5. PostgreSQL migrations
use the same supported version path. A newer, unsupported schema is refused rather than modified.
Mixed-version rolling upgrades are not supported for 1.0.0; use the maintenance-window procedure in
the [deployment guide](../deployment.md).

## Production boundary

AgentBarrier must be the only route to consequential credentials and clients. It cannot prevent an
agent from using an unmediated copy of the original tool. A process failure after execution begins
is recorded as an unknown outcome and requires downstream reconciliation; it is never retried
blindly. Keep downstream business idempotency as a second boundary.

For shared deployments, terminate TLS and apply request-rate limits at trusted ingress, store auth,
Slack, webhook, and database secrets outside model-writable locations, and alert on unknown or
abandoned actions, invalid receipt chains, exhausted limits, pauses, authorization failures, and
webhook dead letters.

Read the [stability policy](../stability-policy.md), [threat model](../threat-model.md),
[deployment and recovery guide](../deployment.md), and [runtime API reference](../runtime-api.md)
before connecting live tools.

## Verification

The release candidate is accepted only when its exact source revision passes Python 3.10–3.13,
strict typing and formatting, branch coverage, SQLite/PostgreSQL parity, real framework and MCP
installed-wheel audits, multi-user authorization, signed webhook and Slack lifecycles,
OpenTelemetry privacy checks, upgrade/backup/restore exercises, and the production container drill.
The tag version must match both built distribution metadata files, and PyPI publication verifies
the uploaded filenames and SHA-256 digests.
