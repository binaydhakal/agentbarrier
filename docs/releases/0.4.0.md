# AgentBarrier 0.4.0

AgentBarrier 0.4.0 adds a real runtime approval boundary alongside the existing deterministic test
harness. Applications can now enforce ordered policy immediately before a consequential Python
function executes, pause an exact request for review, and replay the durable result without calling
the effect twice.

## Highlights

- Ordered `allow`, `deny`, and `require_approval` policy with strict JSON parsing and a published
  JSON Schema.
- Sync and async protected Python functions with canonical arguments, required business
  idempotency, exact policy-version binding, and fail-closed JSON validation.
- Concurrency-safe SQLite lifecycle state, atomic cross-process execution claims, approval expiry,
  durable result replay, and schema migrations.
- Execution leases and explicit committed/not-committed reconciliation for uncertain external
  outcomes; unknown actions never retry automatically.
- Local CLI workflows for inspection, approval, rejection, reconciliation, audit-chain verification,
  database status, migration, and integrity-checked backup.
- Integrity-linked receipts, a runtime API reference and threat model, a credential-free refund
  example, and a clean-wheel end-to-end release audit.

## Upgrade notes

- Runtime state is new in 0.4.0; opening a supported SQLite database applies migrations atomically.
- Back up runtime state before upgrades with `agentbarrier database backup`.
- Policy order is significant and the first matching rule wins. Use an explicit deny default and
  increment the policy version whenever reviewed policy semantics change.
- The local 0.4 CLI trusts operating-system access and records, but does not authenticate, the
  supplied reviewer identity. Authenticated service approvals are planned for 0.5.
